## TL;DR (For humans)

**What you'll get:** A new MikroTik tab in Verkkokyylä: live CPU, memory, uptime, temperature, and fan readings from your router; a table of every interface with traffic and error counters and live speeds; VLAN listings; a panel showing your RouterOS version vs the latest release (with changelog) and bootloader firmware status; one-click configuration backups saved to your PC; and browsable history of past monitoring sessions — all matching the app's existing look.

**Why this approach:** The app already has a proven pattern for live tools (Rust engine streaming over channels to a React view with SQLite history), and the MikroTik work follows it exactly. Two load-bearing choices you approved: passwords live in the OS keyring (never in the app's database), and backups are pulled off the router over SFTP because MikroTik's REST API can't send the backup file itself.

**What it will NOT do:** It never changes anything on the router (no upgrades, no settings edits) — monitoring and backup only. It requires RouterOS v7.1 or newer. One router at a time; no alerting.

**Effort:** Large
**Risk:** Medium - the one un-mockable assumption is that the chosen SSH/SFTP library interoperates with RouterOS's own SSH server; it's a conditional release gate in the final QA wave — smoke-tested against real hardware, and if no router is reachable the release waits for your explicit waiver. A secondary platform risk: Linux credential storage needs DBus/Secret Service available (documented; a conditional Linux build check is in the final wave).
**Decisions to sanity-check:** backups need the router's SSH service enabled (in addition to its HTTPS/REST service); accepting unknown SSH host keys for LAN routers is accepted and documented; interface stats snapshots are not pruned automatically (consistent with the app's other tools — delete sessions to reclaim space).

## Scope
### Must have
1. New "MikroTik" tab in the sidebar nav (hash `#/mikrotik`), rendered via the existing route-to-view map.
2. Connection profiles: name, host, port, TLS on/off, "accept self-signed certificate" toggle, username; password stored in the OS keyring (never in SQLite); profile create/edit/delete with confirm dialog; "Test connection" action.
3. Monitoring session: start/stop against a selected profile; cancellable tokio polling task; base tick 5s fetching `/rest/system/resource` + interface counters via `POST /rest/interface/print` with `{"stats": "", ".proplist": ...}` (a bare `GET /rest/interface` is metadata-only for our purposes, NOT the counter source); `/rest/system/health` every 2nd tick; interface stats-detail + ethernet stats every 6th tick; VLANs (`/rest/interface/vlan` + `/rest/interface/bridge/vlan`) fetched at session start and every 12th tick (60s); live rx/tx rates computed locally from cumulative byte-counter deltas using ACTUAL elapsed time between ticks (monotonic clock), wrap/reset safe (new < old → rate is null that tick); snapshots (resources, sensors, interfaces, VLANs) streamed to the frontend as ONE Tauri Channel event per tick; snapshots persisted to SQLite; version/firmware status persisted on the session row; history panel listing past sessions with load/delete (like TraceSessionPanel), where a loaded historical session renders identically to a live one (graphs, tables, version/firmware state included).
4. System health panel: CPU load %, memory used/total, uptime, board name, RouterOS version, architecture; temperature/fan/voltage derived from a parsed SENSOR LIST — RouterOS health returns either a property set or an array of `name`/`value`/`type` records with possibly MULTIPLE sensors (e.g. `temperature`, `cpu-temperature`, `fan1-speed`); the parser handles both shapes, well-known sensor names map to cards, and a card absent from the list renders an explicit "not supported on this device" state (never shown as 0).
5. Interface table: every interface — name, type, running/disabled state, cumulative rx/tx bytes and packets (via `POST /rest/interface/print` with stats), tx-queue-drop, link-downs; best-effort error counters from `/rest/interface` base fields + stats-detail / `/rest/interface/ethernet` (rx-error, tx-error, rx-drop, rx-error-events, tx-error-events, rx-fcs-error, tx-collision, tx-drop — shown when the driver provides them, "-" otherwise); live rx/tx rates per interface; negotiated link rate/duplex for ethernet (best-effort monitor call).
6. VLAN view: `/rest/interface/vlan` (name, vlan-id, parent interface, running/disabled) and `/rest/interface/bridge/vlan` (vlan-ids, tagged, untagged, current-tagged, current-untagged).
7. Version & firmware panel: RouterOS installed vs latest-available + channel + status from `/rest/system/package/update`; update check triggered once per monitoring session start (POST `check-for-updates`, then bounded poll of the update resource until status is final, ~30s timeout) plus a manual "Check for updates" button; absent `latest-version` renders "unknown", never "up to date". RouterBOARD `current-firmware` vs `upgrade-firmware` (upgrade available iff they differ); "not applicable" state ONLY when `/system/routerboard` parses with routerboard=false or returns 404/no-such-command (CHR/x86/i386); transient errors (timeout/5xx/403/parse) show "unknown", never N/A. Changelog for the latest version fetched app-side from `https://download.mikrotik.com/routeros/<latest-version>/CHANGELOG` (plain text, 404-tolerant), displayed in a scrollable monospace panel, cached per version string.
8. Configuration backup: button opens a dialog (backup name default `verkkokyyla-<yyyymmdd>-<hhmmss>`, optional backup encryption password, include .rsc export checkbox, destination DIRECTORY chosen via the Tauri dialog plugin's `open({ directory: true })`); flow = POST `/rest/system/backup/save` (+ optional POST `/rest/export` with file=), SFTP download (russh + russh-sftp, password auth, accept-unknown-host-key) of `<name>.backup` and optionally `<name>.rsc` into the chosen directory, then delete the temp file(s) on the router (resolve filename → `.id` via `/rest/file`, then `DELETE /rest/file/{.id}`); result returns every saved local path; clear typed error when the router's SSH service is unreachable/disabled.
9. Graphs (uPlot, existing wrapper pattern): CPU load %, memory usage, and rx/tx rates for the selected interface, rendered from the live session buffer.
10. Tests-after coverage: Rust unit + integration tests against a mock REST server (dev-dependency `wiremock`) and a fake SFTP trait implementation; vitest for frontend parsing/formatting/hook logic; Playwright e2e via extended `e2e/mock-ipc.ts`; README updated with the new tab.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- NO writes to router configuration: no upgrades, no setting changes, no reboot. Only backup/export file creation (inherently write-ish) and its temp-file cleanup. Read-only everywhere else.
- NO RouterOS v6 support (REST requires v7.1+ over HTTPS via `www-ssl`; plaintext HTTP only works on v7.9+ via `www`); surface a clear "RouterOS v7.1+ required" error ONLY on REST 404 from `/rest/system/resource` — a 401 is always an authentication failure, never a version signal.
- NO alerting/notifications, NO multi-router simultaneous monitoring (single active session), NO FTP/TFTP retrieval, NO inline-export attempt, NO custom SSH ports (SFTP backup assumes the router's default SSH port 22 — documented in README; a profile has no ssh_port field).
- NO passwords in SQLite, logs, channel events, or persisted frontend state; the profile-form password and the backup encryption password may exist transiently in dialog state and command arguments only, must be cleared after use, and must never be persisted or logged; keyring is the only persistent secret store (service `com.verkkokyyla.app`, account = the profile's random `secret_key`, never the DB rowid).
- NO `anyhow` (thiserror typed errors per repo convention); NO `as any` / `@ts-ignore`; NO empty catch blocks.
- NO raw hex colors in new CSS — DESIGN.md tokens only (`src/App.css`); NO drop shadows (tonal-shift only).
- NO persistent REST monitor streams (unsupported by RouterOS) — polling only.
- NO new raw CSS colors / styling outside `.module.css` files co-located with components.
